## Signals

A **signal** holds a value that layers read on every frame. Wherever a prop is a `ScaleType`, a color, or `opacity` / `text`, you can pass a signal instead of a plain value.

```ts
import { createSignal } from "@nmmty/lazycanvas";

const x = createSignal(40);
const color = createSignal("#ef4444");

new Morph({
  position: { x, y: 60 },
  size: { width: 48, height: 48 },
  color,
});
```

`signal.value()` reads it, `signal.set(v)` changes it immediately, and `signal.reset()` returns to the initial value.

## Tweens

`signal.to(target, seconds, { easing })` returns an animation (a generator) that moves the signal:

```ts
function* move() {
  yield* x.to(440, 1.2, { easing: Easing.easeInOutCubic });
}
```

Colors tween through RGB by default; create the signal with `createSignal("#f00", { colorSpace: "hsl" })` to tween through HSL. Numbers, colors and `{ x, y }` points are interpolated; pass `interpolator` in the config for other types (without one a value snaps to the target at the end).

`Easing` has `linear`, `easeIn`/`easeOut`/`easeInOut` and the `Cubic`, `Quart`, `Quint`, `Sine`, `Expo`, `Circ`, `Back`, `Elastic` and `Bounce` families of each.

## Springs

`signal.spring(target, config)` moves a signal by physics instead of on a schedule. There is no duration: it runs until it settles.

<Example name="springs" caption="Green: default spring. Orange: wobbly spring. Blue: keyframes." />

```ts
yield* x.spring(300);                                  // default: smooth, no overshoot
yield* x.spring(300, "wobbly");                        // a preset
yield* x.spring(300, { stiffness: 120, damping: 8 });  // your own
```

`stiffness` pulls towards the target (higher is faster), `damping` takes energy out (lower bounces more), `mass` makes it heavier. The presets are `default`, `gentle`, `wobbly`, `stiff`, `snappy`, `slow` and `molasses`.

- The motion is solved exactly, so it is identical at any frame rate, and scrubbing a scene back and forth gives the same picture.
- A numeric signal that is already moving keeps its speed (`signal.velocity()`), so a spring that interrupts a tween or another spring continues smoothly. Pass `velocity` in the config to override it.
- Colours and `{ x, y }` points work too: they are blended with the spring's motion, starting from rest.
- "Settled" means within 0.1% of the distance and slower than 1% of the distance per second, so a small and a large move take the same time. Set `restDelta` and `restSpeed` for absolute limits.

`Spring` lets you read the motion itself: `solveSpring(0, 100, "wobbly").position(0.3)`.

## Keyframes

`signal.keyframes(frames, options)` moves a signal through a list of values.

```ts
yield* x.keyframes([
  { at: 0, value: 40 },
  { at: 0.4, value: 300, easing: Easing.easeOutCubic },
  { at: 1, value: 120 },
]);

yield* x.keyframes([0, 100, 50], { duration: 2 });          // plain values, evenly spaced
yield* x.keyframes(
  [{ offset: 0.2, value: 100 }, { offset: 1, value: 0 }],   // offset: 0 to 1 of the duration
  { duration: 3 },
);
```

- `at` is in seconds, `offset` a fraction of `options.duration`. If the first keyframe is later than `0`, the signal starts from its current value.
- A keyframe's `easing` shapes the stretch that **starts** there, as in CSS; `options.easing` is the default.
- Two keyframes at the same time make a jump.
- Colours (`colorSpace: "hsl"` to blend in HSL) and `{ x, y }` points work like in `to()`.

`Keyframes` is also a plain function of time: `new Keyframes(frames).valueAt(0.7)` has no state, so you can sample it anywhere.

Two helpers make easings: `cubicBezier(0.4, 0, 0.2, 1)` like CSS, and `steps(4)`.

## Timeline

`timeline()` places animations on a shared clock. The second argument of `add` is the position, as in GSAP:

```ts
import { timeline } from "@nmmty/lazycanvas";

const tl = timeline()
  .add(x.to(300, 1))               // 0 – 1: at the end of the timeline by default
  .add(opacity.to(1, 0.5), "<")    // together with the previous one
  .add(y.spring(80), ">-=0.2")     // 0.2 s before the previous one ends
  .label("end")
  .add(color.to("#ef4444", 0.4), "end+=0.5")
  .add(otherTimeline, 2);          // timelines nest

scene.addAnimation(tl.play());
tl.duration;                       // seconds
```

| Position | Means |
| --- | --- |
| `2` | 2 s from the start |
| *(left out)* | at the end of the timeline |
| `"<"` / `">"` | where the previous animation starts / ends |
| `"+=0.5"` / `"-=0.5"` | 0.5 s after / before the end of the timeline |
| `"<+=0.2"`, `">-=0.1"` | an offset from the previous start / end |
| `"name"`, `"name+=0.3"` | at a label, and after it |

Positions that depend on an end need to know how long the previous animation is. `to`, `spring`, `keyframes`, `waitFor`, `all`, `chain`, `delay` and nested timelines know it (`durationOf(animation)`); a generator you wrote yourself does not, and `add` says so. Use an absolute position there, or `after(generator)`, which starts when the previous animation really ends. A spring counts as the time it needs to settle from where the signal is when the spring is created.

## Stagger

`stagger` runs animations side by side, each starting a little after the one before:

```ts
yield* stagger(0.08, bars.map((height) => height.to(200, 0.5)));

// or from a list of things and a function that makes the animation for each
yield* stagger({ each: 0.05, from: "center" }, dots, (opacity) => opacity.to(1, 0.3));
```

| Option | Does |
| --- | --- |
| `each` | Seconds between one start and the next. |
| `total` | Seconds from the first start to the last, instead of `each`. |
| `from` | `"start"` (default), `"end"`, `"center"`, `"edges"`, `"random"`, or the index to start from. |
| `ease` | Reshapes the spacing: `Easing.easeIn` bunches the first starts together. |
| `seed` | For `from: "random"`: the same seed gives the same order. |

`staggerDelays(count, options)` returns the delays if you want them yourself. A stagger knows its length, so it can go in a `timeline()`.

## Playing, pausing and reversing

A scene can show **any** time in any order, so pause, reverse, speed and loops are only a matter of which time you ask for. `Playhead` does that arithmetic:

```ts
import { Playhead } from "@nmmty/lazycanvas";

const head = new Playhead({ duration: scene.duration, loop: true, yoyo: true });
head.play();                // pause(), reverse(), seek(t), speed = 2, ...

let last = performance.now();
function frame(now: number) {
  scene.renderFrame(head.tick((now - last) / 1000));
  last = now;
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

Going back uses the history the scene keeps (see below).

## Composing

Animations are generators, so you compose them with `yield*`:

| Helper | Does |
| --- | --- |
| `all(a, b, …)` | Runs animations in parallel and waits for all. |
| `chain(a, b, …)` | Runs them one after another. |
| `waitFor(seconds)` | Pauses. |
| `delay(seconds, a)` | Waits, then runs `a`. |
| `loop(() => a, times?)` | Repeats; forever by default. |
| `loopFor(() => a, seconds)` | Repeats until the time is up. |
| `any(a, b, …)` | Runs in parallel until one finishes. |
| `sequence`, `yoyo` | Value lists and ping-pong. |
| `signal.spring()`, `signal.keyframes()`, `timeline()`, `stagger()` | Physics, keyframes, a timeline with positions and staggered starts: see below. |

```ts
scene.addAnimation(function* () {
  yield* all(x.to(440, 1), color.to("#3b82f6", 1));
  yield* waitFor(0.3);
  yield* x.to(40, 1);
});
```

## Time and seeking

Time advances in fixed steps of 1/240 s, whatever the frame rate, so the same animation looks the same at 30, 60 or 144 fps. A frame time is rounded down to a step.

`scene.renderFrame(t)` accepts **any** time, in any order. Going forward runs the animations; going back puts the signals back from a history the scene keeps while it plays:

```ts
await scene.renderFrame(2);    // plays up to 2 s
await scene.renderFrame(0.5);  // back to 0.5 s: same picture as playing from the start
await scene.renderFrame(3);    // and on
```

The history keeps ten minutes or a million recorded values, whichever comes first, and only records the signals that changed. A scene with a few dozen signals keeps all ten minutes; one with thousands of moving signals keeps a few seconds. `new Scene(w, h, { adapter, history: { maxSeconds: 60, maxEntries: 5_000_000 } })` changes that, `history: false` turns it off (going back then throws). Only the signals the scene knows about are restored: those used as layer props, and those passed to `playAnimation`. Going back further than the history reaches throws an error that says so.

If you move back and then add a new animation while others are still running, `addAnimation` throws, because the running ones cannot be moved back. Call `scene.clearAnimations()` and `scene.resetTimeline()` first.

`scene.duration` is the length of the animations added **as functions** (`scene.addAnimation(() => intro())`). A generator that was already created cannot be run twice to measure it, so it is not counted.

### What it costs

Time moves in steps of 1/240 s, and every running animation is advanced once per step: at 60 fps that is four steps per frame. For a typical scene this is far below the cost of drawing, but with thousands of animated signals it adds up, and the history adds a little more. Two options trade accuracy for speed:

- `new Scene(w, h, { adapter, timeStep: 1 / 60 })` advances once per 60 fps frame (a frame at another rate is rounded down to a step).
- `history: false` stops recording; going back in time then throws.

## Playing a scene

The scene owns the timeline. How you advance it depends on where you run.

### Browser, by hand

```ts
scene.addAnimation(myAnimation);

function frame(now: number) {
  scene.renderFrame((now - start) / 1000);
  requestAnimationFrame(frame);
}
const start = performance.now();
requestAnimationFrame(frame);
```

`scene.hasActiveAnimations()` tells you when the animation has finished; `scene.clearAnimations()` and `scene.resetTimeline()` restart it (also reset the signals with `resetSignals(x, color)`).

### React

`<Scene animated>` runs this loop for you — see the [React guide](/docs/react).

### Node.js, to a file

Render the timeline into an animated PNG:

```ts
import { calculateSequentialDuration, resetSignals } from "@nmmty/lazycanvas";

const duration = calculateSequentialDuration([() => intro(), () => outro()]);
resetSignals(x, color); // measuring ran the animation: put the signals back

scene.addAnimation(chain(intro(), outro()));

await new Exporter(scene).export("apng", { duration, fps: 30, name: "move", saveAsFile: true });
```

The APNG exporter renders `duration` seconds at `fps` frames per second. `calculateDuration`, `calculateParallelDuration` and `calculateSequentialDuration` measure how long an animation takes.

You can also grab frames yourself: `await scene.renderAnimation(0, 2, 30)` returns PNG buffers (or data URLs in the browser) for t = 0…2 s, and `renderAnimationData` returns raw RGBA frames for your own encoder.
